# Calendar subscriptions

The existing token URL stays stable. It is a live read-only ICS feed, fetched on each request. Google Calendar chooses its own polling schedule: clicking Add again cannot trigger a refresh. The app deliberately does not claim an account is linked or that Google has fetched an update.

Deploy backend and frontend together. Hibernate ddl-auto=update adds nullable event time_zone, updated_at and sequence columns. Old wall-clock event dates are interpreted as Europe/Madrid (confirmed by the project owner); new events store an explicit IANA zone. Event DTO startsAt is the absolute instant used for each viewer's local display. Event editing retains the original wall-clock time and its labeled zone. The feed emits UTC DTSTART values and stable UIDs, revision sequence and modification timestamps. Pre-existing subscription URLs do not change; Google receives corrected data on its next fetch.

Use the Google Calendar dialog's Open action for an existing subscription. Add for the first time / From URL creates the subscription once. Download .ics is an unsynced snapshot generated by the same server feed. Keep subscription URLs private. This is not Google OAuth/API synchronization; immediate server-pushed changes would require a configured Google OAuth application and user authorization.

Validation runs in GitHub Actions only. Tests cover summer/winter conversion, other zones/date boundaries, UTF-8 folding/escaping, stable IDs, and live add/edit/delete feed changes. No guarantees can be made about Google's refresh latency, and the user's actual Google subscription is not modified by these tests.
